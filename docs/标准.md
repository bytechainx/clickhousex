# clickhousex 标准

**crate**：`clickhousex` v0.1.0 · 依赖：`reqwest`（rustls）、`tokio`、`serde` / `serde_json`、`thiserror`、`toml`、`tracing`、`url`

## 1. 定位

clickhousex 提供 ClickHouse HTTP 协议的客户端与并发受控连接池原语：连接复用、`max_in_flight`
信号量背压、查询（`TabSeparated`）、`JSONEachRow` 批量写入、认证（Basic 头或 URL 参数）、
TLS（含 mTLS）与健康检查。它不包含领域模型、业务表结构或调度编排，零内部耦合。

## 2. 字段治理

- 环境变量前缀统一为 `FOUNDATIONX_CLICKHOUSEX_`；公开 `ENV_*` 常量，禁止调用方硬编码字符串。
- TOML 采用扁平字段并强制 `schema_version = 1`；未知键拒绝解析。
- `timeout` / `acquire_timeout` 在 TOML 中对应 `timeout_ms` / `acquire_timeout_ms`（毫秒整数）。
- 密码不是 TOML 字段：`from_toml()` 遇到非空 `password` 直接报错；密码只能经环境变量或
  builder 注入，`Debug` 输出固定脱敏为 `***`。
- `FOUNDATIONX_CLICKHOUSEX_PORT` 是兼容别名；与 `HTTP_PORT` 冲突时立即报错而非静默取其一。

## 3. 安全约定

- 非 loopback 主机使用明文 HTTP 会在建立连接前被拒绝，除非显式配置
  `FOUNDATIONX_CLICKHOUSEX_PLAIN_HTTP_HOSTS` 放行名单（仅内网/CI）。
- 错误映射只保留 HTTP 状态码与 ClickHouse 数字错误码（如 `server_code=60`），
  不回显服务端响应正文、SQL 片段或凭据。
- TLS 默认校验服务端证书；自定义 CA 仅在 `tls = true` 时允许配置。
- mTLS 客户端证书与私钥必须成对提供。

## 4. 失败与并发

- `ClickHousePool` 以 `max_in_flight` 信号量做全局背压；等待许可受 `acquire_timeout` 约束，
  超时返回可重试错误。
- `ClickHouseClient` 为单连接语义：请求串行化，不做池化。
- `close()` 拒绝新请求并等待在途操作；`is_closed()` / `stats()` 提供生命周期与计数快照。
- `health_check()` 失败不返回 `Err`，以 `ClickHouseHealth.healthy = false` 表达。
- 可重试判定统一走 `ClickHouseError::is_retryable()`：网络 / IO / 超时 / HTTP 429 / 5xx /
  ClickHouse `159` 为可重试；配置错误、参数错误、序列化错误、认证失败与业务错误不可重试。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
```

测试全部离线运行：纯函数与配置用例不触碰网络，HTTP 用例使用本地一次性 TCP 服务，
失败路径统一用 `127.0.0.1:1`（必然拒绝连接）。至少覆盖配置四入口与校验、密码脱敏与
TOML 拒收、端口别名冲突、`TabSeparated` 解析边界、分块计算、HTTP 往返、不可达失败路径
与公开 API 面。
